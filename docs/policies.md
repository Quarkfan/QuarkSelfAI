# 自然语言策略

## 目标

常东旭只需要描述期望，不需要学习命令或 JSON。例如：

> 重庆平伟群里，只有明确 @我 且包含截止时间的消息才实时提醒；其他消息进入当日汇总。

系统不会每次收到消息都把这段话重新交给模型。owner 私聊总控调用 Claude Code/Codex 将它编译为受限
`PolicyDocument`，本地验证器拒绝未知字段、任意表达式、脚本、外部调用和过深条件，然后使用最近的脱敏事件样本重新模拟。

## 生效流程

1. 保存原始自然语言，生成新的 draft revision。
2. 确定性验证 DSL，不信任模型生成的模拟数字。
3. 用本地样本计算命中数、静默/汇总/实时数量以及紧急消息误抑制数。
4. 策略若会静默、批量延迟、忽略任务或改变回复方式，必须通过带按钮和补充输入框的飞书卡片明确确认。
5. `urgentSuppressedCount > 0` 或本地样本少于 20 条、条件字段缺少覆盖时禁止激活，必须先缩小范围、补充样本或提供安全覆盖设计。
6. 激活只修改 `active_revision`；旧 revision 永久保留，可审计和回滚。

## 当前 DSL

允许的事实限定为聊天类型、是否外部群、会话/发送人 ID、消息文本、是否 @本人、是否包含截止时间、关系类型、业务标签、当前注意力和紧急度。效果限定为：

- 注意力：不变、静默、批量汇总、实时；
- 滴答投影：不变、忽略、创建或更新；
- 回复：禁止、只生成草稿、向本人询问；
- settle window 与少量标签。

策略不能直接发送消息、调用 shell、修改文件、执行 SQL 或选择秘密字段。

## 总控接入

本人私聊仍由 Codex/Claude 总控直接理解，不做枚举分类。识别为长期策略时，总控调用
`quark_policy_propose` 提交候选 DSL；控制层用最近 200 条本地脱敏事件重新模拟并保存草案，然后发送
交互卡片。只有针对具体 policy ID/revision 的“确认启用”回调才调用激活接口。重复提交相同自然语言和
文档会复用内容寻址 ID 与 revision，不重复创建策略或卡片。

代码和契约测试已接通；在现网消费者切换前仍需用真实脱敏样本回放并完成一次受控卡片演练，因此接管
manifest 暂时保持 `partial`。

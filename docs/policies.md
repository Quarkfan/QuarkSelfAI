# 自然语言策略

## 目标

常东旭只需要描述期望，不需要学习命令或 JSON。例如：

> 重庆平伟群里，只有明确 @我 且包含截止时间的消息才实时提醒；其他消息进入当日汇总。

系统不会每次收到消息都把这段话重新交给模型。owner 私聊总控调用 Claude Code/Codex 将它编译为受限
`PolicyDocument`，本地验证器拒绝未知字段、任意表达式、脚本、外部调用和过深条件，然后使用最近的脱敏事件样本重新模拟。

## 生效流程

1. 保存原始自然语言，生成新的 draft revision。
2. 确定性验证 DSL，不信任模型生成的模拟数字。
3. 用本地样本计算命中数、静默/汇总/实时数量以及紧急消息误抑制数。
4. 策略若会静默、批量延迟、忽略任务或改变回复方式，必须通过带按钮和补充输入框的飞书卡片明确确认。
5. `urgentSuppressedCount > 0` 或本地样本少于 20 条、条件字段缺少覆盖时禁止激活，必须先缩小范围、补充样本或提供安全覆盖设计。
6. 激活只修改 `active_revision`；旧 revision 永久保留，可审计。回滚是显式重新激活指定旧 revision，
   同样要求针对该动作的 owner 确认，不能由模型自行执行。

## 当前 DSL

允许的事实限定为聊天类型、是否外部群、会话/发送人 ID、消息文本、是否 @本人、是否包含截止时间、关系类型、业务标签、当前注意力和紧急度。效果限定为：

- 注意力：不变、静默、批量汇总、实时；
- 滴答投影：不变、忽略、创建或更新；
- 回复：禁止、只生成草稿、向本人询问；
- settle window 与少量标签。

策略不能直接发送消息、调用 shell、修改文件、执行 SQL 或选择秘密字段。

## 总控接入

本人私聊仍由 Codex/Claude 总控直接理解，不做枚举分类。识别为长期策略时，总控调用
`quark_policy_propose` 提交候选 DSL；控制层用最近 200 条本地脱敏事件重新模拟并保存草案，然后发送
交互卡片。只有针对具体 policy ID/revision 的“确认启用”回调才调用激活接口。重复提交相同自然语言和
文档会复用内容寻址 ID 与 revision，不重复创建策略或卡片。

## 从协作反馈中学习

系统把重点消息的实际处理结果、注意力建议、本人私聊中的明确回复/纠正信号，以及研究、跟进和策略卡片的
批准或否决记录为脱敏特征。原消息正文和任务标题不进入学习状态。学习器每天评估一次，至少需要 20 条总体
样本和同一精确来源 8 条重复样本；只有 75% 以上通知可合并且没有 @本人、特别关注、紧急、审批、追问或
调研样本时，才允许生成 `attention=batch` 草案。

草案继续走原有确定性模拟和 Card 2.0 批准链路；模拟发现任何紧急消息可能被延迟时不会提示启用。全局每周
最多提出一项模式，否决结果会保留，避免反复建议。同一机制以后可以扩展任务组织和上下文偏好，但任何外联、
正式回复、任务忽略、调研调用和高影响写操作仍不得从统计模式自动获得授权。

批准后的 `attention=batch` 通过本地控制面匹配现网消息并进入持久汇总队列，默认最长 6 小时发送一次合并
卡片；失败时保留队列退避重试。控制面不可用时继续按原决策通知，不因策略服务异常静默消息。明确 @、特别
关注、紧急、审批和调研样本不会由自动学习器生成批量策略；人工策略仍须通过同一紧急样本模拟门禁。

代码和契约测试已接通。2026-08-22 的现网 Card 2.0 批准后，隔离 SQLite 使用 20 条固定合成样本完成
幂等提案、第二 revision、激活和回滚，未产生外部写入，也未改变现网消费者。该能力的接管 manifest
已标记为 `complete`；以后新增策略仍必须逐条经过相同的模拟和批准门禁。

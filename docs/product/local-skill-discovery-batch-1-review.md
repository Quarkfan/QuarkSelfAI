# 本地 Skill 按需发现：第一批独立复评

日期：2026-10-12。结论：允许实施离线元数据采集，不允许挂载现网或把采集视为执行授权。

评估了直接让模型遍历所有 Skill、维护手工目录、扩展现有索引三种路径。直接遍历会导致 token 和隐私成本随目录增长，并绕过作用域；手工目录容易漂移为第二真源；扩展既有索引可保持“显式刷新、少量发现、按需详情”的两级入口，因此选第三种。

关键风险与控制：本地目录可能包含私有信息，采集必须限制在调用方显式指定的根，输出仅逻辑根 ID、Skill ID、简短描述和元数据摘要；symlink 与目录越界失败关闭。`SKILL.md` 是不可信输入，frontmatter 仅作为候选元数据，不是指令。描述可能含恶意文本，未来送入模型前仍须标注来源并按不可信内容处理。重复逻辑 ID 不静默覆盖。目录变化后索引会过期，因此调用方须显式刷新并重新编译；本批不承诺自动监测。

剩余门禁：真实用户/租户作用域、安装状态、授权、签名与审计、语义评测、跨 Codex/Claude Code/DSH 的路由回放均未实现。未取得这些证据前，所有本地 Skill 候选继续标记为不可执行。本复评只批准本地可逆代码和合成测试，不扩大生产、第三方代码或外部写权限。

补充复评（2026-10-12）：首次完整检查揭示 module catalog 的每个新模块必须同时有 migration disposition。把只读元数据 scanner 归入现有 `platform-core` 组符合其长期本地元数据基础设施属性；它仍是 inactive provider，登记仅满足设计和 offer 追踪，不是激活。批准该精确登记后继续实现与复测。

第二次复评：后续完整测试只剩两处静态计数漂移，均由新增的单一已登记模块产生；不涉及运行行为或授权。精确加一是恰当更新，但最终仍以全套测试和提交后架构检查为准。

# QuarkSelfAI 项目章程

状态：正式立项，Phase 2（备份与恢复实现）

Owner：常东旭

产品角色：本地优先的个人 CTO、CIO 与工作助理运行系统

## 1. 使命

QuarkSelfAI 把个人助理的长期协作能力从某一台电脑、某一个聊天会话或某一个模型供应商中解耦出来。任何受信任
终端都应能从代码仓库开始，通过重新登录账号并恢复一份加密状态包，重建同一套安全边界、知识、任务连续性和
工作方式。

## 2. 成功标准

项目最终同时满足以下条件才算具备可恢复性：

1. 在全新 macOS 或 Linux 终端 clone 指定 Git revision 后，可按唯一文档完成依赖安装、配置和启动。
2. 不把任何密钥写入 Git；账号可重新登录，必须保留的应用凭证可从独立加密资源恢复。
3. SQLite 与 PostgreSQL 都有一致性备份、校验、版本兼容和恢复演练；默认本地单实例仍使用 SQLite。
4. DSH profile、策略、审批、事项、幂等检查点、能力进化记录和必要的个人知识具有明确真源。
5. 恢复后通过登录、数据库、DSH、飞书、滴答、执行器、单消费者和控制台端到端门禁，才允许恢复外部写入。
6. 黑湖科技的业务知识、租户数据、客户上下文、公司凭证和内部仓库不是产品主线依赖。
7. 能力进化可周期性参考外部 DevOps 设计，但采纳内容必须带来源和许可证审查，复制为仓库内独立资产后才能依赖。

建议的首版服务目标是 RPO 24 小时、全新终端 RTO 60 分钟；该值在第一次真实恢复演练后调整。

## 3. 产品范围

主线包含：

- DSH/Cordis 插件内核、会话与执行器路由；
- 个人消息、日历、任务、工作账本、知识与策略的可插拔能力；
- 确定性权限、审批、幂等、单写者、数据保留和通知门禁；
- 本地优先运行、受限文件访问、Web 控制台与可选服务器运行；
- 备份、恢复、迁移、可观察性和持续能力进化。

主线不包含：

- 任一雇主、客户或项目的业务事实、内部人员映射、租户数据与生产操作知识；
- 对 BlackLakeWork、公司 Jira/GitLab/Lakers 或任何其他工作区的硬编码路径和启动依赖；
- Codex/Claude 的完整历史、遥测、缓存、插件下载物或模型供应商私有状态；
- 未经批准的对外承诺、生产写入、凭证变更和高影响本机配置修改。

工作领域能力只能作为可卸载 integration pack 安装。未安装时，核心产品仍须构建、启动并通过核心检查。

## 4. 架构原则

- **仓库是程序真源，恢复包是状态真源，密码管理器是秘密真源。** 三者职责不得混用。
- **本地优先，不等于单机绑定。** 本地文件和 CLI 能力保留，但路径、身份和设备差异必须可配置。
- **恢复先只读，写入后放行。** 新终端启动时先禁用消息消费者和外部写插件，通过恢复门禁后再接管。
- **一个逻辑数据只选一个权威副本。** SQLite、PostgreSQL、飞书、滴答和执行器 session 不能互相伪装成备份。
- **最小可恢复集。** 只备份恢复协作连续性所需数据，不复制数 GB 的缓存、日志、遥测与可重新下载资产。
- **外部参考不成为隐式依赖。** 采纳的设计必须在本仓库内可审计、可测试、可离线理解。

## 5. 阶段与门禁

### Phase 1：真源与恢复基线（当前）

完成独立文档、机器清单、数据分类、账号分类、BlackLake 边界和资源申请。2026-09-05 已选择 iCloud Drive
filesystem provider 和 age/X25519 身份；代码提交后 `audit:recovery` 应不再报告资源缺口。

### Phase 2：备份与恢复实现

实现 SQLite 在线快照、PostgreSQL 逻辑备份、加密归档、校验清单、保留策略和只读恢复。不得把秘密写入仓库，
不得在同机目录冒充异机备份。

### Phase 3：独立主线拆分

把现有 BlackLake 专用模块、配置、文档和测试迁移到可卸载的私有工作包；核心构建和恢复流程不读取 BlackLakeWork。
迁移需保持现网单消费者、审批和回滚能力，不能直接删除在用模块。

### Phase 4：全新终端演练

在干净终端从 Git revision 和加密恢复包开始，完成登录、恢复、启动、只读核验、单写者切换与回滚演练。保存
revision、备份 ID、哈希、耗时和缺口；演练通过后才宣称“随时可恢复”。

## 6. 变更治理

- 核心协议、数据格式、备份范围与外部写入门禁使用 ADR 和测试治理。
- 备份内容变更必须同步机器清单、恢复文档和恢复测试。
- 能力进化每个工作日继续运行；外部 DevOps 候选只有在复制入库、去业务化、许可与安全审查通过后才能成为主线依赖。
- 任何恢复演练不得启动第二个飞书消费者；切换必须使用可验证 checkpoint 和维护窗口。

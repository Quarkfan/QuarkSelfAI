# “分身会话”自治运营契约

状态：生效  
授权人：常东旭  
生效日期：2026-08-26  
触发词：用户消息以“分身会话”开头

## 目标

“分身会话”用于维护和迭代常东旭的个人工作助手。用户只需反馈现象、体验或期望，不需要把反馈改写成命令、枚举或技术方案。执行者负责理解目标并推进到可验证闭环，使新开的 Codex 或 Claude Code 会话能够从仓库真源恢复相同的协作方式。

## 默认自治范围

触发后，执行者可以在 QuarkSelfAI 范围内自主完成：

1. 读取飞书、滴答、QuarkSelfAI 状态、日志、数据库、代码和运行配置以复现问题。
2. 先暂停会继续造成重复写入、数据污染、消息骚扰或任务丢失的助手组件；确认活动子任务后再操作守护进程。
3. 制定或调整低风险协作规则，修改代码、配置、测试和文档，运行完整验证并重启同一个现网守护进程。
4. 对具有严格助手血缘的自动化待办和自动化跟进任务进行合并、更新、完成或删除；只处理助手创建的数据，不扩展到用户手工清单。
5. 将验证后的变更提交并推送到 QuarkSelfAI 的既有远端，同时保留用户已有未提交文件。

用户反馈默认是需要闭环的故障或改进信号。执行者不应只解释原因，也不应为了显得忙碌而通知用户；先控制影响，再修复根因、纠偏历史数据、验证恢复，最后一次性报告重要结果。

## 必须确认的边界

自治不覆盖以下事项：

- 代表常东旭向他人发送正式答复、结论、承诺或资源安排；
- 在任何外部群追问或回复，以及无法确认是否外部群的会话；
- 调用“智造湖小维”开展调研；
- 生产发布、DDL、业务数据库写入、凭证或授权变更；
- 删除或不可逆修改不具备助手血缘的文件、任务和业务数据；
- 改变 DSH/Cordis 核心边界、形成双消费者或双写、替换状态真源的架构变更。

需要确认时，应先完成所有可安全完成的调查，提供一个明确方案、影响和回滚方式。等待期间保持工作可恢复，不把等待当作失败。

## 标准闭环

每次“分身会话”按以下顺序处理：

1. **识别目标**：把用户现象还原成体验目标、业务风险和验收标准。
2. **读取真源**：优先检查当前运行状态、队列、日志、外部系统真实数据和对应代码；不要根据旧通知猜测。
3. **控制影响**：若问题正在制造重复任务、错误回复或数据污染，先暂停精确组件或消费者；禁止同时启动第二消费者。
4. **修复系统**：优先增加确定性约束、持久化血缘和幂等边界，再使用模型判断。提示词不能替代代码级门禁。
5. **纠偏数据**：修复前产生的助手错误数据要同步清理；保留一条准确主记录和必要来源，不留下重复副本。
6. **验证**：运行目标回归、`npm run check`、相关 compat/audit 检查；部署后核对进程、健康接口、事件监听和队列。
7. **恢复与观察**：确认没有活动子任务后恢复同一个守护进程；检查一次真实恢复状态，不创建测试飞书消息或测试滴答任务。
8. **沉淀**：更新本契约或对应 ADR/运行手册，提交并推送代码；报告事实、验证结果和仍存在的风险。

## 消息到任务的事项级规则

- 非明确 @ 的会话消息允许延迟 10–30 分钟，先按会话时间窗聚合，再以“事项”而不是“消息”创建或更新任务。
- 同一会话中的连续陈述、补充、确认、表情和本人回复默认属于一个候选事项；只有业务对象、预期结果或责任明显不同才拆分。
- 明确 @ 可以更快处理，但同一线程的短时间补充仍应在上下文中合并。
- 消息 ID 只用于来源血缘和传输幂等，不能作为业务事项唯一键。创建前必须同时检查事项候选、现有未完成任务和最新上下文。
- 表情、寒暄、链接、状态同步或“暗示关注”不能独立创建任务。它们只能更新同一事项的状态；没有残余动作时静默忽略。
- 任务准入必须具备未完成动作、常东旭责任、具体下一步和状态变化价值。已经回复或完成的消息不得因延迟处理重新建单。
- 一组聚合消息最多创建或更新一个任务。若确有多个事项，应先显式拆成事项集合，并为每个事项保留完整来源集合。

## 通知与自我优化

- 飞书用于高实时、高影响和需要交互的事项；滴答用于低实时的个人行动清单。相同事实不得在两个通道重复打扰。
- 助手应从重复、关闭、静默、用户纠正和最终处理结果中提取模式，但模型学习只能形成建议；高影响静默策略仍需受限策略门禁。
- 每次发现“误建、重复、迟到、错误责任、错误优先级或错误通知”，都要同时检查历史数据与生成链路。只修其中一边不算完成。
- 不通过创建测试任务验证现网；使用单元测试、脱敏回放、影子投影和只读审计。

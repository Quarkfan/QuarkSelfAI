# ADR 0087：从真实经验编译 Skill，而不是让运行时直接自改

## 背景

WikiSkill（arXiv:2608.27454v1）提出 Raw、Wiki、Skill 三层结构：执行轨迹先汇总为持续知识，再生成候选 Skill，最后用验证集门禁和回滚决定是否采用。它证明持久知识有助于 Skill 演进，但实验直接注入全部 Skill，没有验证大规模 Skill 检索；其 Raw 层保存完整推理轨迹、Wiki 只增不减，且单一准确率门禁无法覆盖个人助手的隐私、审批、打扰和跨执行器风险。

QuarkSelfAI 已有能力进化巡检、助手知识库、Codex/Claude Code/DSH 执行器以及确定性审批门禁，需要的是连接这些层的经验编译契约，而不是第二个调度器、状态真源或可以绕过批准的自动修改器。

## 决策

采用论文的分层思想，并按个人助手边界改造为以下三层：

1. **Experience**：只保留脱敏的任务指纹、动作结果、纠正/成功/失败状态、时间和短摘要。不得保存飞书正文、完整工具输出、凭证、本地文件清单或模型思维链。
2. **Pattern**：把多个不同任务的证据与反证汇总为有状态的知识模式。模式必须可标记为 `current`、`superseded` 或 `stale`，并允许设置有效期；不能采用论文中永久只增不减的 Wiki。
3. **Skill candidate**：候选必须维持 `shadow`，记录目的、来源模式和目标执行器。Skill 内容继续遵守现有 `SKILL.md + references/scripts/evals` 结构，知识模式本身不直接成为运行时授权。

新增纯函数 `assessSkillPromotion` 作为确定性安全壳。模型可以提出模式、阈值建议和 Skill 草案，但以下门禁由代码执行：

- 所有经验均已脱敏，且不含原文和思维链；
- 来源、模式和任务指纹血缘完整，重复记录不能伪造证据数量；
- Codex、Claude Code、DSH native 中被声明为目标的执行器分别完成验证，阻断跨模型负迁移；
- 触发精确率、召回率、样本量、效果增益和允许回归量由每轮显式策略提供，不固化为不可调整的业务常数；
- 安全或审批违规必须为零；任何目标执行器超过回归预算立即拒绝；
- 编译器最高只返回 `eligible-for-review`，不得自动激活、安装依赖、修改运行配置或发布 Skill。

## 架构边界

`skill-evolution-compiler` 是 `feature/policy/inactive` 纯函数模块。它已经可供离线评测调用，但尚未接入任何运行时；没有 Cordis 插件、定时器、数据库表、外部写入或飞书消费者。现有能力进化 Codex 任务仍是唯一巡检调度；控制台继续只读。未来若要持久化 Experience/Pattern、调用模型生成草案或自动部署 Skill，必须另设模块和 ADR，并复用既有 durable action、workspace、审批及单写者边界。

编译知识与业务知识保持分离：前者记录 Skill 修改证据、反例和效果；后者供具体任务恢复业务上下文。运行 Agent 不直接读取完整编译历史，以免用 Wiki 内容掩盖 Skill 的触发或执行缺陷。

## 当前落地与验证

第一阶段只实现无副作用的编译门禁与单元测试，覆盖：合格候选只能进入评审、隐私/安全/审批/负迁移立即拒绝、陈旧或缺少跨执行器验证时保持影子、同一任务的重复记录不增加证据数。没有读取真实消息、创建测试任务、激活 Skill 或重启守护进程。

后续是否增加模式提炼和离线评测，由真实重复失败与纠正样本触发；没有明确收益时不继续扩建。回滚可删除该纯函数模块、测试和本 ADR，不影响 DSH/Cordis、现网消费者、状态真源或已有 Skill。

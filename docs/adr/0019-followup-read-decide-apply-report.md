# ADR 0019: 跟进巡检按读取、判断、写入、报告分段

状态：已接受（2026-08-24）

## 背景

旧的工作日跟进 effect 只有日期和时区，却被命名为“evaluate”，同时模型返回的 `updates` 被 workflow 直接描述为
“已维护”。它既没有可靠的活动任务快照，也没有证明任何任务真正写入成功；通知和外联甚至可能在任务更新失败时
先发出。这把读取、推理、写入和报告四种责任混为一体，会产生虚假完成。

## 决策

工作日跟进由 durable workflow 串联四个阶段：

1. `task-store.list-active.v1` 从精确清单读取有界活动任务快照，不写入。
2. `assistant.followup.evaluate.v1` 把快照作为不可信数据交给结构化 DSH 推理，只返回更新建议、提醒和外联建议。
3. 每个更新建议通过 `assistant.task-projection.apply-followup-update.v1` 携带 owner 授权独立写入并读后复核；任一
   更新失败时本轮不报告完成，下一调度周期用幂等血缘继续。
4. 所有任务更新成功后，才发送“已维护”摘要、跟进提醒，并为需要联系他人的事项创建后续审批 workflow。

任务存储、模型判断、滴答投影和飞书通知分别由独立 provider 实现。长期等待由 workflow state/wakeAt 保存，模型
调用和通知都不拥有私有 timer。

## 结果

“建议更新”不再冒充“已经更新”，通知顺序由 durable 状态机证明。跟进清单未来替换任务产品或推理模型时，不需要
重写调度与审批状态机。

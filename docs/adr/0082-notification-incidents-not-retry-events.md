# ADR 0082：通知面向事项和故障，不面向每次重试

状态：accepted

## 背景

兼容链路曾把每条重点消息的首次处理失败直接发给 owner，并用模型返回的原始截止时间字符串作为超期提醒指纹。
同一时刻的不同 ISO 表示、模型生成的非可信任务链接以及一组消息的共同基础设施故障，会因此变成大量看似独立的
通知。内部重试细节淹没了真正需要批准或处理的事项。

## 决策

1. 超期提醒以 `taskId + 规范化 UTC 截止时间 + priority` 去重；兼容状态中的等价旧指纹只迁移，不补发。
2. 任务链接只能从受信任的 projectId 和 taskId 生成，不消费模型或 provider 返回的任意 URL。
3. 重点消息处理失败按一个持续故障批次聚合。默认至少持续 30 分钟且累计 5 次才通知一次；单条消息、原文、SQL、
   图片和内部 prompt 不进入故障通知。
4. 未曾通知的瞬时故障恢复时保持静默；只有已通知的持续故障才发送一次恢复摘要。
5. 需要 owner 批准、授权或明确操作的业务事项仍走独立交互卡片，不被基础设施故障批次吞并。
6. 控制台必须显示聚合处理故障和积压数，让“静默自动恢复”不等于“不可观测”。

## 结果

重试频率可以根据恢复需要调整，但不会等比例增加用户通知。通知数量由事项变化、批准需求和故障生命周期决定，
而不是由轮询次数、消息条数或模型字符串格式决定。

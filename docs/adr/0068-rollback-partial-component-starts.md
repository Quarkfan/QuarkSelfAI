# ADR-0068：生命周期主管必须回滚部分启动的组件

状态：Accepted（2026-08-25）

## 问题

进程级组件的 `start()` 可能在创建子进程、监听端口或注册定时器之后失败。生命周期主管此前只回滚已经完整返回的
组件，不会调用失败组件自己的 `stop()`，因此一次失败启动可能遗留资源。若回滚其他组件也失败，回滚异常还会覆盖
最初的启动异常，导致控制台和日志丢失真正的首个失败点。

组件的长期故障 watcher 也可能 reject 而不是 resolve 一个 `Error`；此前这种 provider 偏差会成为未处理的 Promise
rejection，绕开统一故障状态。

## 决策

- 在调用 `start()` 之前把组件放入逆序回滚栈，要求进程级组件的 `stop()` 对部分启动状态安全；
- 启动失败时先尝试逆序停止失败组件和此前组件，再把失败组件状态恢复为原始启动错误；
- 回滚也失败时抛出同时包含启动错误和回滚错误的 `AggregateError`，不丢失任一证据；
- 将 failure watcher 的 reject 归一化为组件故障，与正常 resolve 的故障走同一条生命周期链路。

## 结果

应用装配失败不再默认泄漏部分资源，首个失败点与清理失败都可诊断。业务插件仍使用 DSH/Cordis 生命周期；这项语义
只约束稳定应用宿主中的进程级组件。
